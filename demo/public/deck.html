x402-svm
HTTP-native payments for the agent economy on Solana

Every API endpoint becomes a vending machine. Every agent gets a wallet.

The problem

  • AI agents now browse, negotiate and call tools — but HTTP has no way to charge machines per request.
  • Monetization is built for humans: API keys, KYC, invoices, chargebacks.
  • Result: data stays behind logins, agents scrape or hallucinate, providers can't price per-call.

The insight

HTTP already has a status code for payment: 402 Payment Required. It shipped unused in 1992.

Solana makes it real: ~$0.00002 per settlement, ~400 ms finality, no allowances.

Product

SDK (TypeScript)
wrapFetchWithPayment(fetch, conn, wallet)
one line makes any agent pay-per-request. Server helpers build terms and verify settlements on-chain.
Live paid API
SOL/USD quotes at 0.001 USDC, premium research at 0.01 USDC — settled on-chain, verified from chain state, served in the same second.
  • Wire-compatible with the x402 spec; SVM adaptation documented.
  • No approve/allowance: direct transferChecked, destination derived, memo-stamped.

Demo — working today

  • Live paid API + agent loop: demo URL in submission
  • Settlement receipts: real SPL transfers, verification reads chain state (amount + destination + success), never client claims.
  • Public repo with full source, spec mapping and roadmap.
