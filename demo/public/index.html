x402-svm

Payment Required — machine-native, on Solana devnet live

AI agents need to buy things over HTTP: a price quote, an article, an inference call. Today that means API keys, KYC, invoices — human plumbing. x402-svm implements the x402 protocol on Solana: a server answers 402 Payment Required with machine-readable terms, the agent pays a SPL token transfer (USDC) on-chain, and retries once. Total added latency: about a second. No accounts. No keys. No paperwork.

1 · GET
agent requests a resource
2 · 402
server returns payment terms
3 · PAY
agent sends a USDC transferChecked
4 · RETRY
X-PAYMENT header → 200 OK

Try it

Point any HTTP client at the live paid endpoints on devnet:

GET /api/price    0.001 USDC → SOL/USD spot
GET /api/premium  0.01 USDC  → research note
GET /api/stats    free payment ledger
GET /api/health   free liveness

Every settlement is a real Solana transaction — see the ledger below and click through signatures on Solana Explorer (devnet).

Why Solana

  • Fee per payment signature ≈ $0.00002 — micro-pricing viable
  • ~400 ms finality keeps pay-then-retry inside one agent tick
  • No approvals: direct transferChecked, no allowance risk
  • Wallet-native agent runtimes (e.g. OOBE/Steve) need exactly this

Stack

  • sdk/ — terms builder, envelope codec, wrapFetchWithPayment(), on-chain verifier
  • demo/ — this paid API + demo agent
  • Spec mapping — EVM x402 → SVM: ATA derivation, transferChecked, memo provenance
  • Zero build: runs on Node ≥ 22 via --experimental-strip-types
